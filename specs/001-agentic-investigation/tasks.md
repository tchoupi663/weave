## Dependencies & Execution Order

- **Setup (Phase 1)**: no dependencies.

- **Polish (Phase 7)**: depends on the stories it documents.

### User Story Dependencies

- US1 is the MVP and first deliverable.
- US2 can be implemented in parallel with US1 after the token/config scaffolding; its smoke test uses a manual incident.
- US3 requires both US1 and US2.
- US4 follows US3.

- Tests are written before implementation where the task lists them.
- Shared DTO/schema/config tasks precede handlers and evaluators.
- Server tools precede the investigator loop; scope enforcement precedes every tool.
- Benchmark environments/fixtures must be validated before the harness pilot.

## Implementation Strategy

### MVP First

US1 alone delivers detection: a healthy run produces no incident, the catalog
fault produces one incident with a trigger, and it closes automatically. This
is the first demonstrable slice and should be completed and accepted before
the agent work.

### Incremental Delivery

1. US1 detection + metrics API.
2. US2 scope, MCP servers, investigator with a manual fixture incident.
3. US3 profile, scenarios, harness, pilot.
4. US3 full matrix + docs.
5. US4 seam review and polish.

### Notes

- The benchmark's 5-minute baseline is profile configuration, not a product
  change; the 15-minute default remains for manual and production incidents.
- Ground truth, scenario files, and fault-injection metadata are never exposed
  to the agent; the harness owns them.
- A failed or capped run is recorded, not silently retried into a different
  result.
- The full matrix is run once on a clean tree and recorded; do not tune the
  comparison after seeing its result.
